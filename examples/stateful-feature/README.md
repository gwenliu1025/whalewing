# 保存文本：持久化二级插件示例

独立 DSH 开发包，在鲸翼中提供「保存文本」页签。只保存当前 profile 的一条文本，用来演示自己的 Remote、原生数据域、版本冲突、真实提交后读回、取消、关闭保留及显式清除。没有默认定时任务、外部服务、模型或网络请求；不读写个人知识及其它插件。

完整接口、安装、卸载和源码删除规则只在鲸翼包根的 [EXTENDING.md](../../EXTENDING.md)。复制本目录到独立项目后，从配套 `dsh-whalewing` 安装包根目录读取同名文件，或取得该版本的完整开源源码。此 README 只说明本示例。

## 开发与安装

1. 复制整个目录到自己的独立源码仓库。在 `package.json` 修改 `name` 和 `whalewingExtension.id`，再修改说明、locale、图标及界面。其余身份从包声明派生；包名也是持久数据身份，已经保存数据后改包名不会自动迁移数据。
2. 在本目录执行：

```sh
npm install
npm run build
npm test
```

3. 使用独立 DSH 测试 profile，安装配套鲸翼，再在原生「添加插件」填 `link:<此目录绝对路径>` 并启用。本示例不修改鲸翼的组成清单或主 patch。
4. 打开「保存文本」，点「编辑文本」，在右侧抽屉输入并保存；成功提示发生在原生域提交和读回一致之后。重启/重开后点刷新核对数据。预置 `client.js` 仅适用于原样模板，修改后必须构建。

运行时使用 DSH 原生 `typert`、`storageDomain`、`profileContext`；平台服务缺席时原生插件行等待。`package.json` peers 声明实际开发依赖；React 保持 external。当前开发示例不是发布版本，鲸翼 peer 范围以首个带 v1 的封版版本为准。

本例客户端在 `$mount` 后单独注入自己的 `remote.<namespace>`，只从就绪子作用域调用它；挂载成功本身不等于该作用域已有调用依赖。重连、超时或断开会撤销原作用域及挂载，迟到结果只清理。

## 本示例的数据和失败行为

- 数据域按包名和当前真实 profile 路径派生，只有 `settings/text` 一条文本记录。每次操作持原生文件锁，重新打开域；本实例忙时拒收第二个请求，不建立无界队列。
- 编辑读取当前 revision，保存按该 revision 比较。冲突时保留表单，刷新查看最新文本，再关闭并重新编辑；不自动用旧草稿覆盖新版本。
- 请求有十秒取消信号，开始提交前可取消；磁盘提交已经开始时仍等待真实结果和关闭资源。停止等待不证明磁盘未修改，下一步是刷新核对，不盲目重发。
- 普通关闭/卸载只停止新操作、排空已经接受的操作并释放资源，不清数据。重装同包名、同 profile 后可继续读取。
- 「清除保存文本」使用独立确认弹窗，准确清除当前 profile 保存的 1 条文本。清除不删除知识、会话、计划、源码或其它插件数据。只保留无正文的 revision 空值标记以防旧窗口覆盖；重复清除已空数据返回当前空状态。若要清除文本，应在原生卸载之前执行并读回。
- 原生卸载不删除开发源码；源码删除前按公开规范检查所有已知 `link:` 消费者。已经卸载后要清除数据，先恢复原匹配版本，通过自己的清除入口操作，不猜测原生存储物理目录。

## 验证范围

`npm test` 使用真实 Cordis、TypertRegistry、storageDomain 与 JSON 存储后端，在系统临时目录中验证保存/关闭/重开、CAS、清除、失败重试、取消、写入排空、锁争用及 profile 隔离；结束清理自己的临时目录。鲸翼登记只模拟公开边界，不导入鲸翼内部实现。

客户端契约及构建测试不替代真实网页操作。交付前还须在独立 profile 验证缺鲸翼时等待、总开关、扩展开关、编辑/冲突/清除、冷启动、原生卸载及旧页签无迟到更新。只生成浏览器产物，不自动打分发包或发布。
