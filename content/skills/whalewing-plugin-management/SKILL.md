# 鲸翼插件开发与管理

直接完成用户当前要求的插件工作，并以实际结果核验。技能提供工作方法，不替代 DSH 的原生管理器、工具审批或扩展自己的数据管理接口。

## 找准对象与说明

1. 区分本次是查询、开关功能、开发、接入、卸载、删除源码还是清除数据。它们不是同一动作；“关闭”不默认删包，“卸载”不默认删源码或数据。已有明确要求直接执行，缺少会改变删除范围的对象才询问。
2. 使用本轮“鲸翼管理资料”给出的真实安装目录和文档位置。技能可能被复制到个人技能区，不从本文件向上猜插件根目录；也不把旧会话中的路径或版本当现状。
3. 操作当前 profile 时先用实际可见的 `plugin_manager` 查询插件行和 bundle，按 `nextOffset` 读完相关分页。功能开关使用查询返回的准确 `entryId`，包操作使用实际包名；功能 id、标题、原生行 id 和包名不能混用。
4. 按任务只读对应说明：
   - 安装、数据位置及用户恢复：当前包 `README.md`。
   - 二级插件开发、公开 API、资源退出、卸载、源码删除和清数据：当前包 `EXTENDING.md`。
   - 维护鲸翼主代码、职责边界、构建和回归：对应完整源码的 `MAINTAINING.md`。
   - 无存储功能从 `examples/feature-starter` 开始；确需保存状态时看 `examples/stateful-feature`。不把示例的业务规则当作所有插件的要求。

管理工具缺席或原生依赖未就绪时，先报告实际缺口并定位原生插件页；不通过编辑 profile、复制管理器或更换权限模式伪装工具已就绪。用户指定开发目录时可以先做不依赖该工具的源码工作。

## 原生查询、开关与安装

- 使用当前工具 schema 的 `list_plugins`、`list_bundles`、`set_plugin`、`set_bundle`、`install_bundle`、`remove_bundle`。已有工具和原生审批就是执行入口，不再写一套包安装或开关脚本。
- 改动按用户的准确对象执行。开发联调用明确的绝对 `link:` 目录；固定版本安装与兼容声明按扩展说明处理。安装脚本批准、版本豁免必须分别取得工具所要求的明确同意，不用普通安装要求代替。
- 结果按真实 `application` 解释：`applied` 才表示已应用；`restart-required` 是已保存待重启；`overridden` 是被更高层覆盖；`failed` 或 `cancelled` 保留原诊断。`changed` 只说明磁盘变化，不说明功能已可用。
- 写后重新查询同一原生对象，功能实际加载与页面使用另行核验。未知接受状态先读回，不换新对象重试。按原生 `nextStep` 恢复，未消除原因不循环提交。
- 用户只要求某个功能开关时只改对应可选行，不顺手关闭鲸翼核心、其它插件或整个 profile。

## 开发与维护

先确认工作目录属于目标插件，保留未提交修改和用户配置。主插件维护需要完整且匹配版本的源码、构建脚本和测试；运行时安装目录或 pnpm 缓存不等于开发仓库。通过当前实际来源确定完整源码，缺少来源时询问用户，不猜本机仓库路径或自动覆盖安装缓存。

开发二级插件时复制完整模板到独立项目，按 `EXTENDING.md` 接公开接口，不往鲸翼内置功能目录添加社区包，不导入鲸翼内部源码。按用户目标完成业务实现、失败和取消处理、自己的测试及说明，再到独立 profile 验证原生安装、启用、关闭、重开和卸载；模板代码存在不代表集成通过。

维护主插件时按 `MAINTAINING.md` 找到当前职责和直接消费者，只在一个地方持有业务规则。源码、实际生成物、文档和验证在同一版本闭合，保留已有功能与用户数据。检查由未参与本次语义写入者完成；发布、分发、替换用户正式环境不由普通开发要求自动触发。

## 卸载、删源码与数据

先读取当前包 `EXTENDING.md` 的“关闭、卸载、删除源码与清除数据”及命中的操作小节，按该处完整流程执行和核验；鲸翼自身退出也使用该处的独立接管规则。此技能不维护第二套删除顺序或恢复办法，当前工具的真实 `nextStep` 与该说明一起决定后续动作。

## 交付与退出

给出实际变更、验证结果、保留的数据与源码、尚待重启或人工处理的准确事项及恢复入口。区分源码测试、原生运行、真实模型调用和发布；未执行项不记为通过。用户停止或本次目标已核验后退出，不继续扫描其它插件、资料或 profile。
