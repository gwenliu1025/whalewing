# 知识库规则

本文件持有员工知识库的固定维护规则。专家与定时整理共同读取，不各自解释一套。内容由员工工作积累，原有工程持有业务事实；知识库不是公司共享服务，规则与空模板不包含任何人的个人知识。日常知识和技能生成不修改本规则、基础权限或插件代码。员工日常怎么用见[知识库使用说明](知识库使用说明.md)，作品写作见[作品写作规范](作品写作规范.md)。

## 十区职责与分类

| 目录 | 保存对象 | 不放什么 |
| --- | --- | --- |
| `00-系统` | 规则、导航、模板、索引和维护 | 普通业务笔记 |
| `10-收件箱` | 尚未确定价值或归属的输入 | 原始资料正文、附件、长期正式版本 |
| `20-项目` | 有目标和完成条件的事项 | 无结束条件的长期责任 |
| `30-领域` | 持续维护的责任 | 一次性交付任务 |
| `40-知识` | 消化后可独立理解和复用的认识 | 未消化的原文堆积 |
| `50-来源` | 外部资料来源及其上下文 | 原始资料正文、摘录、转写和附件 |
| `60-时间线` | 按发生时间记录的事实和回顾 | 脱离时间即可复用的知识 |
| `70-作品` | 面向交付的成果及索引 | 仅供过程参考的素材 |
| `80-外部索引` | 库外原件的位置、用途和使用边界 | 外部资产本体 |
| `90-归档` | 已结束、失效但仍需追溯的内容 | 当前活跃版本 |

先判断归属和保留价值。已经确认要保留、尚未消化的外部材料，通过 `80-外部索引` 登记待整理原件，原件继续留在库外受控位置，并遵守该资料所在位置的规则；不因尚未消化就放入收件箱。归属或保留价值仍不明确的输入进入 `10-收件箱`。明确属于项目的记录直接进入项目，其余按有结束条件的项目、长期领域、自身形成的知识、外部来源、时间记录、交付作品、外部原件索引、历史归档分别归位。收件箱内容在七天内完成保留、删除、归位或提炼判断，不为凑数量造笔记。PARA 用于责任划分，主题通过 MOC 与双链组织。

初始化预建常用二级目录：`20-项目/工作`、`20-项目/学习`；`30-领域/职业发展`；`40-知识/产品与业务`、`工作方法`、`工程与工具`、`人工智能`、`学习与成长`；`50-来源/书籍`、`网页`、`课程与视频`、`对话与会议`；`60-时间线/日记`、`周记`、`月记`、`人生事件`；`70-作品/报告`、`文章`、`PPT`；`80-外部索引/代码项目`、`工作文件`、`数字资产`；`90-归档/已完成项目`；`00-系统/索引/任务`。优先放进已有目录，确有需要时在对应区内新建同级子目录，不在根级新建十区以外的分类目录。时间线按年份再分一层，例如 `60-时间线/日记/2026/2026-10-14.md`。

同一内容的当前主文件是唯一 owner。其他项目、领域和主题通过属性或链接引用，不复制平行真源；七位专家共享同一库，不拆七库。工作知识按“公司 → 产品 → 客户项目 → 子项目或具体任务”分层：产品通用知识进 `MOC - 产品名`，客户专属知识进 `MOC - 客户项目名`，范围、进度和任务结果进对应项目页。同客户不同系统不自动合并，只有来源证明上下级关系才记录 `parent_project`。月记记录当月工作计划与安排，不强求每天完整，缺失可后补。

## 类型、属性与命名

九种 `type`：`capture` 临时输入、`timeline` 日周月记录、`project` 有结束条件的项目、`area` 长期领域、`source` 外部来源、`atomic` 独立观点、`moc` 主题导航、`output` 自己的成果、`asset-index` 外部索引。归档是状态，不新增类型。新建笔记按 `00-系统/模板` 中对应类型的模板取用骨架，空栏目可以删去，模板文件本身不是业务笔记。

正式知识 Markdown 均有 `type`、`status`、`created`、`updated`、`aliases`。日期为 `YYYY-MM-DD`，新建填写实际日期，更新保留创建日期。按需增加 `source/moc/project/area/url/author/due/location/parent_project`，不铺空字段或重复目录分类。子类型用 `timeline_type`（daily、weekly、monthly）、`source_type`（book、web、course、meeting）、`output_type`、`asset_type` 标注；`captured`、`started`、`finished`、`published`、`actual_date`、`last_checked`、`backup_status`、`external_location` 等有值才写。库外原件不补这些属性；DSH Skill 使用自己的格式，不套用知识笔记属性。

已定义状态：

| 类型 | 状态 |
| --- | --- |
| `capture` | `inbox`、`processed`、`archived` |
| `source` | `unread`、`reading`、`processed` |
| `atomic` | `seedling`、`evergreen` |
| `project` | `active`、`paused`、`completed`、`archived` |
| `output` | `draft`、`reviewing`、`published`、`delivered` |

状态按实际事实选择，不强制逐个经过。其他类型填写实际维护状态，不借用不存在的业务流程；归档项目仍保留 `type: project`。

| 对象 | 文件名 | 示例 |
| --- | --- | --- |
| 日记 | `YYYY-MM-DD` | `2026-10-14` |
| 周记 | `YYYY-Www` | `2026-W42` |
| 月记 | `YYYY-MM` | `2026-10` |
| 人生事件 | `事件 - 日期 - 名称` | `事件 - 2026-10-14 - 入职` |
| 项目 | `项目 - 名称` | `项目 - 供应商数据治理系统` |
| 书籍 | `书籍 - 书名` | `书籍 - 刻意练习` |
| 网页 | `网页 - 标题` | `网页 - 如何建立长期知识系统` |
| 课程 | `课程 - 名称` | `课程 - 大模型应用开发` |
| 主题导航 | `MOC - 主题` | `MOC - 人工智能` |
| 外部索引 | `资产 - 名称` | `资产 - 需求规格说明书` |
| 任务记录 | `YYYY-MM-DD 任务名` | `2026-10-14 月结报表口径纠偏` |
| 原子笔记 | 完整观点 | `稳定反馈比意志力更容易形成习惯` |

日记、周记、月记按年份归入时间线对应目录。标题、H1 与可选 title 保持一致，旧文件仅在确有混乱或获准迁移时改名。

标签只表示待核实、待补充、待输出或敏感等临时状态，主题用 MOC 与双链。成熟原子笔记连接上层 MOC、相关支持/应用/冲突观点，以及必要的外部来源，并在正文解释关系；缺证据或关系时保持幼苗，不伪造引用。

## 来源、原件与修订

原件保留在受控库外位置，外部索引记录真实位置、用途、适用项目/版本及必要备份状态。外部原始资料正文、网页全文、书摘、课程转写、OCR 文本和附件不因转成 Markdown 或已经读过就进入知识库；来源笔记只记来源身份、出处、原件链接、页码或时间位置、保留原因、简短的个人理解和核对状态。读取和修改原件服从当前任务授权；删除索引不删除原件。受限材料只沉淀可保留的经验和必要索引，不把密码、Token、密钥、订阅凭据、客户机密或可识别个人资料写进普通笔记或技能。

项目页持有目标、范围、需求、决定、进度、风险及下一步，不记每日流水；跨项目认识提炼到知识并链接来源。交付物入口放作品，原件位置仍由外部索引指向。结束项目保持原类型，归档到 `90-归档/已完成项目`。

任务关联保留原始目标、用户语义、执行路径、初次结果、纠偏依据、当前结论、防复发方法及覆盖范围；只为值得深入的任务建立完整记录，普通任务保留必要索引。完整任务记录放在 `00-系统/索引/任务`，用 `type: output`、`output_type: task-record`，`actual_date` 填事件日期，进行中为 `draft`，结论确定后为 `published`。返工与错误挂回原任务，不孤立制造失败知识。

`on_hit`、`on_miss`、`on_wrong` 只记录有证据的实际使用、缺失和错误反馈。只有明确纠偏、承认错误或可追溯返工才记 `on_wrong`，模型不确定性不算已发生错误。

修订保留可追溯原文，将被证据替代的结论标为 `superseded`，当前结论标为 `current`；不无痕覆盖历史。多个来源冲突时，以更新时间更近、直接来自原始记录且符合当前规则的文件为准；证据不足时保留冲突并说明，不擅自指定当前版本。冲突未解决保持待确认，高风险业务修订先入收件箱候选。历史材料只按证据修正，只有结构缺口时只补索引和覆盖说明，不猜原始事实。

## 查阅与回答

先按首页和 MOC 定位，再读取完成任务所需的原文；不只依据导航、标题或摘要作答。回答时说明关键依据文件、资料时效和缺失信息。

## 日记、整理与覆盖

按事件发生时间及任务时区归入自然日，日记链接项目、任务及有价值的来源，说明值得保留的内容。日记末尾保留“检查记录”，分清实际完成、未完成和待确认；润色不改变任务状态。周回顾检查进展、待确认判断与超期收件箱；月回顾检查完成项目、作品、领域、外部路径和备份。回顾规则不自动新增周期任务。

定时整理仅消费员工启用范围内的 DSH 会话和选定资料。项目、任务、会话与产物由来源证据定位，不以已有项目名单遗漏已纳入的会话；先读摘要定位，再核对关键原文，不原样保存所有聊天。无来源不等于无工作。

覆盖账本只记录来源的真实读取、核对和写入结果，不持有第二套业务事实。首次处理按员工启用范围开始，后续从成功覆盖范围补齐未处理时段；关机多日后不只处理昨天。未读完、读取失败、写入失败或检查未通过的部分不推进成功覆盖。笔记写后回读和检查成立才提交覆盖，重复触发先查覆盖去重；调度投递不代表整理成功。

当前批次输出实际变更、来源覆盖、验证结果和未完成项。批次完成或具体阻断明确后结束，不循环制造内容，不自动上传或发布。

## 校验与恢复

写前回读并确认当前版本，单写入者避免并发覆盖。删除、移动、合并前盘点引用和资产、检查完整性、保留可恢复依据；未经员工确认不批量移动、覆盖、重命名或删除。改名同步维护链接。写后校验属性、断链、重名、来源和语义；结构通过不替代业务正确。

配置或内容变更先解析，再写入，再回读；保留仍有效旧内容，失败不宣称成功。固定规则升级保留员工笔记：插件只补齐缺失的目录和随包文件，员工改过的随包文件保持原样。生成技能不反向更改规则；所有操作保持实际 DSH 授权，不自行提交、推送、修改客户端或扩大资料范围。
